# AI Studio 设计系统

本文件承接 `frontend-product-redesign-plan.md` 已确定的视觉方向。2026-10-10 起，界面优化按共用规则和页面模式推进，不再在 `workbench.css` 尾部追加页面覆盖。

## 视觉与操作目标

保留中性炭灰、青绿色主操作、清楚的表面层次。用户进入创作页先看到本次内容和下一步动作；进入资源页先看到可选择的资源；进入设置页先理解能力与连接状态。模型来源是每次任务的选择，工作台只有一个产品。本地模型按需安装与启动。

正文使用系统字体，中文使用微软雅黑，正文 15px、表单与操作 13px、辅助说明 12px；页标题 28px，区域标题 18px。主要阅读区使用正常明度，路径、参数与辅助信息降低层级，错误不能只靠颜色区分。间距以 4px 为基础，控件圆角 6px，面板 10px，弹窗 12px。

## 源码职责

| 层 | 唯一职责 | 文件 |
| --- | --- | --- |
| 设计变量 | 色彩、字体、间距、圆角、阴影、动效时长与曲线 | `scripts/design-tokens.css` |
| 基础组件 | 文本、面板、行入口、输入、按钮角色、反馈状态、弹窗、焦点、减少动态效果 | `scripts/ui-components.css/js` |
| 产品框架 | 六项全局导航、页面边距、当前位置、移动导航 | `scripts/workbench.css` / `web_shell.py` |
| 页面模式 | 输入与结果、分阶段编辑、资源集合、服务配置、时间线 | `tool-workspace.css` / `workflow-stages.css` / `library.css` / `online-services.css` / `video-tools.css` |
| 业务页面 | 特有的网格、媒体构图、内容密度；不重复定义颜色与控件皮肤 | 各页面 CSS / JS |

所有页面由服务端在首屏加入同一套设计资产。变量先载入，页面模式定义布局，共用组件定义交互外观，框架只负责框架。新增共享资产必须加入发布清单并验证打包后的路由。旧的 `hub-button`、`btn-primary` 等类作为已有组件的语义入口，不维护另一套皮肤。

组件作用域覆盖正文以及正文外的原生弹窗，由 `web_shell.py` 统一挂载；弹窗自身可以是作用域根。共用弹窗规则同时支持这两种结构，减少动态效果也覆盖根本身。导航仍由框架管理，不通过扩大按钮规则或页面专属覆盖修补浮层。页面模式的普通链接样式不得覆盖按钮链接的文字颜色。

## 组件与状态契约

- 用户明确要求不使用文字下划线：普通链接、导航、工程标题在默认、悬停和键盘聚焦时都遵守。使用颜色、底色、方向提示与共享焦点框表达可操作性；页面样式不得覆盖侧栏交互。正文链接仍应清楚区分于周围文字。
- `section` 只负责语义分组，不自动绘制卡片。需要表面的区域显式使用 `ui-panel`，从同一组变量取得背景、边界、圆角与内边距（桌面 24px，窄屏 16px）。不得只给内容分组铺底色却让文字贴边；编辑器有独立内部分区时在自己的布局中声明内边距。
- 总览页面共用 `--studio-overview-width` 上限，不因宽屏无限拉开短文字；面板标题、说明和操作保持同一条内容边界。`ui-action-row` 用于整行可点入口，`ui-title-link` 用于中性工程标题；其颜色反馈与焦点属于共享组件，页面只决定尺寸和排列。
- 按钮默认次要；主动作显式 `primary` / `btn-primary`，同一区域只强调当前下一步。链接使用按钮外观时必须保持相同文字对比度。刷新、导入、关闭和辅助导航不得抢占主动作。
- 输入可编辑、只读、无效、禁用分别表达；只有正在提交的操作标记 `aria-busy=true`。禁用不是统一的“等待”状态。错误出现在相关内容旁，保留输入并给出可执行的下一步。
- 可编辑的工程/视频标题使用共享 `editable-title`，沿用输入框完整边界与圆角，悬停/聚焦使用同一强调色；不用单条底边模拟标题下划线。表单边界与无效边界使用各自设计变量；不以透明边框让输入看起来像不可编辑标题。
- 长任务区分正在提交、排队、运行、完成、失败、未知。相同输入仍在生成时阻止重复提交，修改输入后允许新任务；旧结果始终标注来源，不覆盖当前编辑。
- 保存操作捕获提交时的快照。返回后仅清除该快照的脏状态；期间的新输入继续保留。切换资源、能力或页面不应让旧响应写进当前对象。
- 生成完成附加媒体与作者修改分别处理。仅在同一计划的一次服务端更新完全属于媒体关联时，允许共享状态层合并；保留本机输入、增删与排序、手工素材及审片意见。服务端存在创作或审片修改仍保留冲突；不以最新到达的响应强行覆盖。保存后键盘焦点返回触发按钮，输入无效时定位具体字段。
- 任务使用提交时的服务与参数，包含火山的资源/表达设置和 ChatGPT 的账号归属。失败续作可更新同一服务的访问凭据，改变账号、端点、模型或音色应作为新任务；不能在排队、模型查询或重试期间悄悄换用当前登录账号。账号标识不包含邮箱或令牌。结果同时说明提交版本和当前计划版本。
- 单步工具共用草稿保护：读取、恢复或保存失败时保留原始内容和当前编辑；发现另一窗口更新时暂停覆盖。恢复必须先完成备份，再保存当前编辑；备份失败优先提供下载，恢复备份在刷新后仍可导出。设置未载入时先保留可编辑字段，载入完成后合并尚未修改的草稿设置。
- 浏览器草稿、跨页带入和任务缓存使用共享 `StudioStorage`，按服务器首屏提供的工作台身份隔离；同一端口换目录不能读到另一安装的草稿。旧版本没有归属的草稿保留原文并提供本地下载，不自动套用到新工作台。跨窗口冲突仍按当前工作台的键判断。
- 资源带入只初始化本次编辑。配音与图像使用共享草稿层，在完整载入并安全保存后才消费地址中的来源参数，保留无关查询与定位；刷新继续使用最新编辑。读取、备份或保存失败时不消费入口，明确恢复成功后再完成带入，避免恢复原入口时重置用户的新参数。
- 资源状态用“可用 / 待准备 / 读取失败”解释，空集合和连接失败不能混用。长名称允许换行，关键动作随卡片底部对齐，路径放进可展开详情。
- 媒体集合（作品库、图库、音频库）共用卡片轨道：封面容器固定 16:9，图片按原比例完整显示，不拉伸或裁掉竖屏作品；音频、文档和缺图占位使用同一容器。标题使用共享 `ui-card-title`，内部文本占两行并截断，完整名称留在可访问名称、悬停提示和详情中。标题不是填色操作按钮；预览使用 `ui-media-preview`，不能被普通按钮的内边距、背景和布局覆盖。
- 同一媒体集合的标题、单行元信息、标签槽和底部操作各占固定轨道；标签最多一行，过长标签截断，状态与收藏始终对齐。网格拉伸卡片，正文以弹性列承接底部操作。窄屏改变列数，不改变封面比例或放开标题行数。音色和模型说明卡片保留必要正文，同排底部操作对齐，不为追求全站等高而隐藏业务说明。
- 方法目录复用工作流卡片与共享控件：方法名称、准备条件、能力边界、创作入口和已有作品共同构成完整入口。目录从固定来源与生产目录投影，不单独维护一份脱节的 Skill 列表；新增方法必须同步网页入口和可编辑示例。带入示例先保存旧计划并建立恢复副本，保存失败时保留输入并定位错误。
- 方法出片复用生成工坊的步骤、任务状态、播放器和下载链接。固定场景与通用创作通过同一表单内的明确选项区分；素材工程使用共享选择控件，不另开主题或外部启动器。显示实际使用的配音与素材，隐藏当前模式不使用的模型控件；提交失败保留输入，结果保留版本来源。
- 窄屏的分类与状态筛选换行展示，不把关键入口藏在横向滚动之外；主按钮保持完整文字。需要保留二维关系的参数表使用局部滚动容器，不压缩为逐字断行，也不让整个页面横向溢出。方法介绍与编辑区之间使用共享间距。
- 原生弹窗保留语义、焦点约束和 Escape 行为；关闭保留草稿。长表单使用 `form-dialog > dialog-form > dialog-body + dialog-actions`：正文独立滚动，操作区位于滚动区之外，控件仍归属原表单。禁止用覆盖正文的 sticky 底栏模拟这一结构。参考试听放在对应参考字段旁，底部主要负责保存与收起。
- 使用长表单结构的页面载入 `ui-components.js`，共用组件在滚动区尺寸变化时保持当前焦点字段可见，只调整必要的局部滚动，不改变焦点、输入或页面数据。视口缩小、操作反馈变高均需实际回归；这条设计要求不等于已完成移动设备软键盘实测。删除、替换须有对应恢复机制。
- 结果页首先呈现已有结果，再提供再次生成的设置。播放器按比例适配可用宽度与视口高度，切换步骤时让结果标题出现在固定操作栏下方。作品详情的下载与继续编辑形成主操作组，跨工作流入口为辅助链接，工程文件收进有数量提示的折叠区。

## 动效契约

反馈只帮助识别操作与位置，不持续装饰。颜色与边框反馈 140ms，按下 100ms，弹窗从下方 8px 进入 180ms，移动导航 200ms；使用同一条减速曲线。弹窗本体全程不透明，避免中间帧与底层文字叠影。关闭立即结束，重复打开不排队；减少动态效果时直接到终态。页面切换不使用整页淡入或无实际动画的 View Transition。

## 验收方式

先看代表页面的实际桌面与窄屏画面，再拓展到其他页面；覆盖长标题、空、失败、运行、完成以及键盘焦点。动效同时检查初始、中间、完成和快速反向操作。工程检查、浏览器过程证据、用户视觉反馈分别记录；尚未听审或运行外部/GPU 能力时不能以测试通过替代。

本轮证据与尚未通过的项目记入 `frontend-product-redesign-plan.md`。禁止把本规范本身当作完成验收的证据。

颜色验收按实际计算样式和背景合成测量：普通文字 4.5:1、大号文字 3:1，必要控件边界与焦点 3:1；禁用状态另记，不用取整后的临界值判通过。参考 W3C 的[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)和[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。颜色计算、可见控件键盘循环和代表图复核各有范围，不能合并宣称完整 WCAG 符合性。
